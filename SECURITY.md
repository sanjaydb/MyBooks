# Security policy

This is an educational repository, not a supported production product. Its security-related examples are intended only for lawful, defensive research in an isolated lab.

## Report privately

Please do not open a public issue if you discover:

- A committed credential, token, password, private key, or personal record
- Confidential or proprietary material
- A sample that unexpectedly performs harmful or network-active behavior
- A vulnerability in repository automation that could expose contributors

Use GitHub's **Report a vulnerability** feature on the repository Security page. Include the affected path, impact, and safe reproduction steps. Do not attach live malware or sensitive data.

Ordinary code corrections and safe hardening suggestions can use the public issue templates.

## Scope

The repository does not accept live malware, exploit chains, persistence mechanisms, credential theft, destructive actions, or code intended for unauthorized access. Maintainers may remove unsafe submissions without notice.
